# 端到端案例

案例围绕一个真实科研问题展开，完整呈现输入、Agent 执行、人工审查、证据和交付物。它们不是功能截图的拼盘，也不会把 SciForge 描述成内置了用户尚未接入的科研模型。

| 案例 | 定位 | 当前状态 | 关键交付物 |
| --- | --- | --- | --- |
| [ECCITE-seq 跨尺度虚拟细胞证据图](./virtual-cell-evidence-atlas.md) | 首发主案例 | 产物浏览已验证；完整 Agent 重跑仍需补齐连续取证 | 扰动审阅表、版本化图表、证据关系、科研档案 |
| [虚拟细胞扰动预测评测](./virtual-cell-benchmark.md) | 进阶集成案例 | 实验性 | 预测文件、契约检查、分层指标、失败分析、复跑记录 |

## 两个案例的分工

第一个案例回答：“如何把已有的跨尺度单细胞分析组织成可审查的证据链？”重点是数据质量、缺失状态、图表溯源和结论边界。

第二个案例回答：“如何把用户已有的扰动预测模型接入一个可复现评测？”重点是防止数据泄漏、固定协议和环境、密封预测，以及区分离线演示与官方线上提交。

## 截图原则

案例主图必须保留 SciForge 应用外壳，包括工作区、任务上下文和当前工具面板。脱离 SciForge 的热图、表格或终端输出只能作为细节附图，不能用来证明产品流程已完成。

## 权限原则

- 查看已有产物可以使用只读沙箱。
- 生成脚本、表格、图表或档案需要工作区写入。
- 下载、登录、远程提交和上传属于外部影响，必须在执行前单独确认。
- 正式案例应在干净的 Git 工作区或项目副本中完成。
