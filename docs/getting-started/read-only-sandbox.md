# 配置只读沙箱

提示词中的“不要修改文件”是一条任务要求；只读沙箱才是系统执行边界。第一次体验、陌生仓库审查和来源不明的任务都应从只读开始。

## 设置位置

1. 打开左下角的 **设置**。
2. 进入 **AI 助手**。
3. 切换到 **权限范围**。
4. 找到本次使用的 Codex 或 Claude Code。
5. 将文件访问范围设置为**只读**。
6. 回到工作台，新建会话，让新设置完整生效。

*图 1：截图定位了文件访问范围。图示值允许修改工作区；只读任务应在同一控件中选择“只读”。*

## 只读模式允许什么

通常可以：

- 列出目录和读取文本文件
- 搜索源码与配置
- 查看 Git 状态和差异
- 执行不会写入工作区的检查
- 给出分析、计划和建议

不应允许：

- 创建、覆盖、重命名或删除文件
- 安装会写入项目的依赖
- 运行会生成缓存、日志或构建产物的命令
- 修改 Git 索引、提交或分支

命令是否真正只读取决于其行为，而不是命令名称。某些测试和解释器会自动生成缓存；不确定时应拒绝执行。

## 双重验证

在 Git 项目中分别于任务前后运行：

```bash
git status --short
```

如果输出发生变化：

1. 立即停止后续任务。
2. 打开工作台的 **变更** 面板核对具体文件。
3. 不要自动删除或还原已有修改。
4. 判断改动来自任务、工具缓存还是任务前已存在的状态。

![SciForge 变更检查面板](/img/docs/guides/workspace-changes.jpg)
*图 2：变更面板用于核对当前会话涉及的文件差异；Git 状态仍应作为独立基线。*

## 什么时候切换到工作区写入

只有当任务明确需要生成脚本、表格、图表或文档，并且你已检查计划与输出路径时，才切换到“可修改工作目录”。写入型任务应使用项目副本或干净分支，并在结束后审查变更。
