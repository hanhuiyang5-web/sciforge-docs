# 与 Agent 协作

高质量任务不是更长的提示词，而是让 Agent 和用户对目标、允许范围、交付物和停止条件达成同一理解。

## 一个可执行任务的四部分

| 部分 | 要回答的问题 | 示例 |
| --- | --- | --- |
| 目标 | 最终要解决什么问题？ | 找出测试失败的根因 |
| 范围 | 可以读取和修改哪里？ | 只看当前包，不改公共 API |
| 约束 | 哪些动作不可自动执行？ | 不安装依赖，不访问外网 |
| 验收 | 怎样证明已经完成？ | 相关测试通过，解释根因与改动 |

推荐模板：

```text
目标：……
范围：……
约束：……
交付物：……
验收方式：……
遇到以下情况请停止：……
```

## 先读、再计划、后写入

对于陌生项目或科研数据，推荐分三轮：

1. **只读分析**：让 Agent 建立项目、数据和风险基线。
2. **计划审查**：检查拟修改文件、输出路径、依赖和验证方法。
3. **执行与验证**：切换到合适权限，完成写入并审查差异。

## 查看执行过程

执行过程中重点检查：

- Agent 当前处理的步骤
- 实际读取的文件
- 工具调用及参数
- 命令、返回码和输出
- 写入文件与目标路径
- 等待用户决定的审批请求

审批不是“继续”按钮。确认前先看操作对象、影响范围、外部目标和恢复方式。

## 修正不完整结果

不要只说“再详细一点”。引用具体缺口：

> 你列出了入口文件，但没有说明从启动到主界面的调用链。继续只读分析，按调用顺序列出函数和源码路径；推测内容单独标注。

## 长任务的切分

把长任务分成可以独立验收的阶段，每个阶段写清输入、输出与停止条件。科研任务尤其应在数据审计失败时停止，而不是继续生成看似完整的图表和报告。
