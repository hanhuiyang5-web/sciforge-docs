# 证据与可复现性

科研任务完成后，一段看似正确的总结并不等于可复现交付。SciForge 使用几类互补对象记录“发生了什么、得到了什么、依据是什么、下一次从哪里继续”。

## 选择正确的记录对象

| 对象 | 解决的问题 | 典型内容 |
| --- | --- | --- |
| **会话** | 任务是如何推进的？ | 消息、工具调用、命令、审批和最终回答 |
| **Artifact Version** | 某个图表或文件如何演变？ | 产物路径、版本、输入与生成信息 |
| **Git Checkpoint** | 工作区文件处于什么阶段？ | Git 状态与阶段性代码快照 |
| **Research Checkpoint** | 一次科研阶段如何继续？ | 研究上下文、关键产物和恢复位置 |
| **Evidence DAG** | 主张由什么支持或反驳？ | 主张、来源、方法、产物、限制及关系 |
| **Research Dossier** | 最终交付如何被他人阅读？ | 研究问题、输入、方法、结果、可信度和局限 |

## 建立一条可复查链

推荐顺序：

1. 在任务开始时记录工作区、输入版本和目标。
2. 在关键计算后保存命令、参数和产物。
3. 对图表或报告建立产物版本。
4. 将关键主张连接到输入、方法与图表。
5. 人工检查反证、缺失数据和推断边界。
6. 保存 Checkpoint，并生成 Research Dossier。

## 让 Agent 留下完整记录

可以在任务中加入：

> 完成分析后，把研究问题、输入文件、使用的方法、关键参数、结果和局限整理到科研档案。每条关键结论应能回到对应来源、派生表或图表；无法确认的内容标记为未验证。

不要只要求“生成 Evidence DAG”。先明确哪些主张值得审查、哪些数据能直接支持它们，以及哪些解释仍是候选假设。

## 人工审查清单

- 每个关键数字能否回到输入文件和计算步骤？
- 图表是否来自已验证派生表，而不是手工改过的中间文件？
- 结论是否混淆关联、预测与因果？
- 反证、warning 和缺失数据是否仍然可见？
- 复跑所需的代码 commit、环境、参数和随机种子是否齐全？
- Checkpoint 是否对应已经核对的 Git 状态？

## 数据边界

Evidence DAG 和 Research Dossier 只有在当前工作区与会话已有相应数据时才会显示有意义的内容。空面板不代表功能故障；先让任务生成明确的主张、来源和产物记录。
