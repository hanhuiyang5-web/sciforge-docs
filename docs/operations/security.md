# 权限与安全

权限配置应与任务目标匹配。更宽的权限不会自动让结果更好，只会扩大错误或误操作的影响范围。

## 文件访问范围

| 范围 | 适合任务 | 主要风险 |
| --- | --- | --- |
| **只读** | 项目理解、代码审查、数据清点和计划 | 某些看似只读的命令可能生成缓存 |
| **可修改工作目录** | 修改代码、生成分析、图表和报告 | 覆盖已有文件、写错目录、混入无关改动 |
| **更广文件访问** | 明确需要跨目录读取或写入的受控任务 | 影响工作区之外的数据与配置 |

第一次任务、陌生仓库和未审查 Skill 应默认使用只读。详情见 [配置只读沙箱](../getting-started/read-only-sandbox.md)。

## 审批策略

审批请求至少应说明：

- 将执行什么操作
- 目标文件、目录、主机或外部服务
- 是否会写入、上传、发送或删除
- 失败后能否安全重试
- 如何检查结果和恢复

仅靠拒绝审批不能替代只读沙箱；默认允许的工作区写入可能根本不会触发审批。

## 凭据

- API Key、Token 和密码不要写入提示词、Git 仓库或截图。
- MCP、模型 API 和协作服务使用各自所需的最小凭据范围。
- 不要把 Provider Key 当作 Runtime 登录凭据。
- 导出日志、trace 或科研档案前检查 Authorization header、服务器地址、真实路径和样本隐私。

## Computer Use

Computer Use 可能操作其他桌面应用，因此同时受 SciForge 设置、Backend 状态和 macOS 屏幕录制/辅助功能权限约束。

![SciForge Computer Use 权限状态](/img/docs/guides/ai-assistants-computer-use.jpg)
*图 1：启用前同时核对允许的 Runtime、Backend 和操作系统权限。*

以下动作应在执行当下由用户确认：账号登录或授权、发送消息、上传数据、购买或付款、删除外部内容、提交正式评测结果。

## 科研数据安全

- 用公开或可再分发数据制作教程。
- 原始数据默认不覆盖，派生结果写入独立目录。
- 远程工作区中的数据是否允许下载由项目政策决定。
- 外部模型、MCP 和网页上传会改变数据边界，必须单独评估。
- 截图应隐藏真实账号、密钥、患者信息和服务器细节。

## 任务前检查

- [ ] 工作区或项目副本正确
- [ ] Git 基线已记录
- [ ] Runtime 与文件访问范围符合任务
- [ ] 输出目录与覆盖策略明确
- [ ] 网络、安装、登录和上传边界明确
- [ ] 验收与恢复方式明确
